# Route data and authentication through Core

All Admin, Student, and Visitor applications access domain data and authentication through the NestJS Core service; authenticated Next.js frontends act as browser-facing BFFs while Core remains the authoritative application and session service backed by Supabase Auth, and clients upload files to R2 only through Core-issued presigned URLs. We chose this boundary over direct browser access to Core authentication or Supabase so authorization, workflow, validation, auditing, session lifecycle, and browser cookies remain isolated by surface, accepting an additional server-to-server hop for authenticated frontend requests.
