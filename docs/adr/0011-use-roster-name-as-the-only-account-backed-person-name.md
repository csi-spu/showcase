# Use Roster Name as the only Account-backed Person name

An Account-backed Student or Alumnus has one authoritative Thai first name and last name established by the Student Roster. Public Profile storage contains no duplicated or editable name. Student and Alumnus surfaces expose Roster Name read-only; only an Admin may change it through a versioned, idempotent, reason-required, audited correction. Core uses the current Roster Name for consented Public Profile reads, People search, Contributor selection, and new Submitter or Account-backed Contributor Attribution Snapshots. Existing immutable Revision snapshots are never rewritten.

We rejected a separate self-managed Display Name because it creates two competing identities, makes Contributor and Submitter attribution inconsistent, and allows a Student to change the public identity independently of the authoritative Roster. We also rejected silently overwriting Roster Name during later imports; conflicting rows continue to require Admin resolution. The accepted cost is that granting Profile Consent publishes the university Roster Name and an Admin correction changes future public profile reads and future snapshots immediately after cache invalidation.
