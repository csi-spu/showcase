# Bind authentication sessions to one frontend BFF

Core stores provider credentials and authoritative Authentication Sessions, while each authenticated Next.js frontend BFF stores only its audience's opaque session token in a host-only cookie on that frontend hostname and forwards the token to BFF-authenticated internal Core endpoints; we rejected direct browser-to-Core authentication, one shared cross-surface session, and parent-domain cookies because they enlarge the credentialed CORS and cross-surface compromise boundary, accepting separate login and logout behavior and one environment-specific server-to-server secret per frontend.
