# Show Student IDs to Instructors

Core retains each Student's raw Student ID in a private table keyed by Account and returns it to authenticated Instructors wherever an Instructor surface lists or searches Students, and every Instructor search that accepts a Roster name also accepts a one-to-eight-digit Student ID prefix. Search keeps using ADR 0013's keyed prefix-hash index, so it covers every Account before the raw value is backfilled; the raw value is only read for display. Roster provisioning writes the raw value, and an idempotent Roster re-import backfills existing Accounts. Student ID still never enters a URL, query string, cursor, log, metric, analytics event, or any Student, Visitor, or Admin response, so Instructor searches send it in a request body.

This supersedes ADR 0018's Roster-name-only identification and ADR 0013's rejection of retaining the raw value; ADR 0013's prefix-hash search boundary for Contributor Candidates remains in force. Instructors need the institutional identifier to recognise Students, and we rejected display-free search because an Instructor cannot confirm which Student matched. We rejected application-level encryption as unnecessary operational cost. We accept that the initial Student password equals the Student ID, so any Instructor can sign in as a Student who has not yet changed it, and that anyone who reads the database or its backups learns every Student's initial credential; the Instructor population is small and trusted.
