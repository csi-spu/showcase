# Build missing images on explicit manual deployment

A manual production deployment may build a selected application's image when no image exists for the requested `main` SHA, but only when the operator sets `build_missing_images`. The workflow builds exactly the missing images through the same build workflow as a CI-triggered deployment, never rebuilds an existing `sha-<commit>` tag, and still passes the protected `production` approval gate. Without the flag, a missing image fails the run as before.

This amends ADR 0015's rule that manual deployment only verifies existing images. CI selects applications by diffing a push against the previous push, so a `main` push whose CI fails leaves its affected applications unbuilt, and the next successful push never selects them again. We rejected pushing no-op changes into affected packages because it disguises a delivery repair as a product change, and re-running the failed CI runs because they redeploy older commits one at a time and may fail on the same defect already fixed on `main`. We accept that a manual build reaches production without a CI-triggered build step, so the operator must choose a `main` SHA whose CI quality gates passed.
