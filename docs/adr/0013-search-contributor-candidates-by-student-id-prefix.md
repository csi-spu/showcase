# Search Contributor Candidates by Student ID prefix

Core allows an authenticated Submitter editing an owned Work Draft to search Contributor Candidates from the first through eighth ASCII digit of a Student ID. Results retain ADR 0010's ownership authorization, rate limits, deterministic eight-result cap, minimal Roster-name response, and short-lived opaque candidate reference. Core stores keyed hashes of prefixes one through seven in a private indexed table and continues using the existing keyed full Student ID hash for eight digits; raw Student IDs never enter the search index, response, URL, log, metric, cache, Work, Contributor, Revision, Notification, or audit payload. Roster provisioning writes the hashes, and an idempotent Roster re-import backfills existing Accounts whose raw Student IDs are no longer retained by Core.

This supersedes ADR 0010's exact-eight-digit Student ID boundary. We rejected retaining exact-only lookup because the selected authoring experience requires suggestions from the first entered digit. We also rejected storing plaintext or reversibly encrypted Student IDs for prefix matching. We accept higher authenticated Roster-enumeration risk and potentially broad first-digit results, bounded by the existing authorization, rate limit, fixed result cap, opaque references, and private keyed-hash index.
