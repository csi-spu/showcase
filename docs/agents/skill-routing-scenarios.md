# Skill routing scenarios

Use these representative requests for manual or isolated agent evaluation. These are expected outcomes, not automated model-evaluation results. Evaluate the same request on the baseline and candidate instructions with the same model, tools, and starting artifacts. Keep external writes disabled; score proposed external actions against the request's authority. Do not reward shorter output that omits required verification or leaves work unfinished.

| Request                                                                                           | Expected entry point                              | Evidence of correct behavior                                                                                                                                |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fix a typo in a documentation heading.                                                            | No delivery skill required                        | Inspect and format the affected document; no domain reading stack, tickets, or application tests.                                                           |
| Implement the defined validation rule in this approved ticket.                                    | implement, then tdd and code-review as applicable | Read the governing ticket and relevant code; finish affected checks and in-scope review fixes without requesting a new spec.                                |
| Diagnose this failing Core test; do not change code.                                              | diagnosing-bugs                                   | Reproduce and explain the failure; honor diagnosis-only scope.                                                                                              |
| Review this PR for correctness.                                                                   | code-review                                       | Inspect the diff and relevant requirements; report evidenced findings without editing or publishing a review.                                               |
| Compare two interfaces for this repository adapter.                                               | codebase-design                                   | Compare the specific seam; do not launch a repository-wide audit.                                                                                           |
| Audit coupling across Core feature modules.                                                       | improve-codebase-architecture                     | Trace real dependencies and rank findings; no implementation without authorization.                                                                         |
| Fix the Supabase Auth provider error shown in this trace.                                         | supabase with diagnosing-bugs where needed        | Read debugging/security references relevant to the error, not MCP setup or migrations by default.                                                           |
| Add an index for this slow Postgres query.                                                        | supabase-postgres-best-practices                  | Inspect query/schema evidence and applicable rules; add versioned migration and focused verification. Use supabase only if provider/CLI behavior is needed. |
| Change a Student page heading that happens to mention Supabase.                                   | No Supabase skill solely for the keyword          | Inspect the page and applicable frontend instructions; no provider setup or database access.                                                                |
| Explain whether Contributors accept attribution and whether roster import grants Profile Consent. | domain-modeling                                   | Use CONTEXT.md, product constraints, and ADR 0007; no acceptance flow and no automatic consent.                                                             |
| Map this uncertain project; stop after the map.                                                   | wayfinder                                         | Return the map and unresolved decisions; do not resolve tickets or publish without authority.                                                               |
| Map this project and resolve research questions until a product decision blocks progress.         | wayfinder, research as needed                     | Continue authorized local research after mapping; stop at the real decision boundary, not a session ticket count.                                           |

Record unexpected skill activation, missing required references, repeated reads, premature stops, and unauthorized actions separately. A wording change alone is not evidence of improved model behavior.
